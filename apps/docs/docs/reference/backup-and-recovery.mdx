Back up Outpost's data directory, key file included, so you can restore the account, the <Terminology title="A key your scripts send to call the API" to="/docs/reference/terminology#api-access">access tokens</Terminology>, the notification <Terminology title="Where your alerts land, like ntfy, Telegram, or email" to="/docs/reference/terminology#notifications">destinations</Terminology>, and the history after a move or a mistake.

## Export and Import

The **Backup** section near the end of **Settings**, just above **Diagnostics**, makes a portable <Terminology title="A JSON backup you can carry to another Outpost" to="/docs/reference/terminology#backup-and-encryption">export file</Terminology> or brings one into this Outpost. Use it to move selected configuration between installations without copying the source <Terminology title="The file that unlocks your saved secrets" to="/docs/reference/terminology#backup-and-encryption">encryption key</Terminology>.

### Export

1. Open **Settings**, scroll to **Backup**, and select **Export…**.
2. Keep every section selected, or clear anything that should stay out of the file.
3. Select **Continue**.
4. Complete <Terminology title="Prove it's you again before an export or import" to="/docs/reference/terminology#backup-and-encryption">**Confirm it’s you**</Terminology>, then select **Confirm**.

The downloaded file is named `outpost-export-YYYY-MM-DD.json`. Its selected sections are:

- **Settings** — Schedule, startup checks, container selection, monitor-only mode, cleanup, and replacement timing.
- **Registries** — Every private registry sign-in, including its saved password.
- **Notifications** — Every <Terminology title="Where your alerts land, like ntfy, Telegram, or email" to="/docs/reference/terminology#notifications">destination</Terminology>, its events and settings, and its <Terminology title="A saved token or password the API never hands back" to="/docs/reference/terminology#notifications">secret fields</Terminology>.
- **Access tokens** — <Terminology title="A key your scripts send to call the API" to="/docs/reference/terminology#api-access">Token</Terminology> names, scopes, expiry, timestamps, and stored hashes. Raw token values are never stored and cannot be put in the file.

:::warning
Registry passwords and notification secrets are plain text in the file. Keep it somewhere safe; an import encrypts them with the destination Outpost's key.
:::

### Confirm It's You

<Terminology title="Prove it's you again before an export or import" to="/docs/reference/terminology#backup-and-encryption">Confirm it’s you</Terminology> asks for the current password and, when the authenticator app is on, its current 6-digit **Authenticator code**. Select **Use a passkey instead** to use a <Terminology title="Sign in with your device, no password or code" to="/docs/reference/terminology#dashboard-sign-in">passkey</Terminology>.

The confirmation lasts five minutes, works once, is limited to export or import, and belongs only to that browser session. Using another browser, waiting longer, or switching operations requires another confirmation.

### Import

1. Open **Settings**, scroll to **Backup**, and select **Import…**.
2. In **Source**, choose **An Outpost export**. The JSON file must be smaller than 10 MB.
3. In **Settings**, compare **In the file** with **Here**.
4. In **Review**, check the exact additions, replacements, and skips, then select **Import**.
5. Complete <Terminology title="Prove it's you again before an export or import" to="/docs/reference/terminology#backup-and-encryption">**Confirm it’s you**</Terminology>, then select **Confirm**.

The wizard finishes with **Importing** and applies every selected section in one database transaction. If any section fails, none of its changes are kept.

- **Settings** — Values in the file replace the current schedule, startup-check, selection, monitor-only, cleanup, and timing values.
- **Registries** — A sign-in for the same host, without regard to letter case, is replaced, including its password. A new host is added.
- **Notifications** — A <Terminology title="Where your alerts land, like ntfy, Telegram, or email" to="/docs/reference/terminology#notifications">destination</Terminology> with the same name, without regard to letter case, is replaced. A new name is added.
- **Access tokens** — A token with a new ID, name, and stored hash is added. A token whose ID, case-insensitive name, or hash already exists is skipped, so an import never creates a duplicate.
- **Sections not in the file** — Existing values in those sections stay as they are.

Imported settings take effect immediately, including rebuilding the active schedule. Imported token hashes keep their existing raw token values working, but the file cannot reveal or reissue those values.

### What Stays Here

An export never contains these, and an import never changes them. **Review** notes that they stay here.

- **Administrator account, password and recovery codes** — They protect this Outpost.
- **Authenticator and passkeys** — They stay bound to this account and hostname.
- **Browser sessions** — Signed-in browsers remain local.
- **Update history** — It describes work performed here.
- **Docker runtime data** — Containers and discovered images are read live.

### Choose an Export or Data Backup

Use the portable <Terminology title="A JSON backup you can carry to another Outpost" to="/docs/reference/terminology#backup-and-encryption">export file</Terminology> for selected configuration. Use the complete data-directory backup below to restore the whole installation, including the account, sign-in security, browser sessions, update history, database, encryption key, and recovery state.

## What Outpost Saves

Everything lives in the data directory, which is `/config` by default:

| Path                                                                           | What it holds                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
|--------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `/config/database/outpost.sqlite3`                                             | The dashboard account, its sign-ins, the <Terminology title="A key your scripts send to call the API" to="/docs/reference/terminology#api-access">access tokens</Terminology>, the authenticator app, the <Terminology title="A spare code for when your authenticator is gone" to="/docs/reference/terminology#dashboard-sign-in">recovery codes</Terminology>, the <Terminology title="Sign in with your device, no password or code" to="/docs/reference/terminology#dashboard-sign-in">passkeys</Terminology>, the notification <Terminology title="Where your alerts land, like ntfy, Telegram, or email" to="/docs/reference/terminology#notifications">destinations</Terminology>, and the private registry sign-ins. |
| `/config/database/outpost.sqlite3-wal`, `/config/database/outpost.sqlite3-shm` | Recent database changes that belong with `outpost.sqlite3`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `/config/keys/installation.key`                                                | The <Terminology title="The file that unlocks your saved secrets" to="/docs/reference/terminology#backup-and-encryption">encryption key</Terminology> that seals the authenticator app's secret, the <Terminology title="A saved token or password the API never hands back" to="/docs/reference/terminology#notifications">secret fields</Terminology> of notification <Terminology title="Where your alerts land, like ntfy, Telegram, or email" to="/docs/reference/terminology#notifications">destinations</Terminology>, and the passwords of private registry sign-ins.                                                                                                                                                |
| `/config/history.json`                                                         | The last 50 checks and updates.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `/config/image-config-cache.json`                                              | Image defaults for images still used by managed containers, so recreation can preserve user overrides if Docker removes an old image record.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `/config/self-update.json`                                                     | An update of Outpost itself that's still in progress, and a new Outpost image that failed to start, which later checks skip. It's gone when there's nothing left to keep.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

- When a new Outpost image fails to start, the previous Outpost starts again on the same data directory. Each release keeps the database readable by the release before it, so the account, the <Terminology title="A key your scripts send to call the API" to="/docs/reference/terminology#api-access">access tokens</Terminology>, the notification <Terminology title="Where your alerts land, like ntfy, Telegram, or email" to="/docs/reference/terminology#notifications">destinations</Terminology>, and the history carry over.
- It is recommended to keep the data directory on a local disk, because the database isn't reliable on network shares such as NFS or SMB.

## The Encryption Key

- Outpost creates the <Terminology title="The file that unlocks your saved secrets" to="/docs/reference/terminology#backup-and-encryption">encryption key</Terminology> on its first start. It encrypts the authenticator app's secret, the <Terminology title="A saved token or password the API never hands back" to="/docs/reference/terminology#notifications">secret fields</Terminology> of notification <Terminology title="Where your alerts land, like ntfy, Telegram, or email" to="/docs/reference/terminology#notifications">destinations</Terminology>, and the passwords of private registry sign-ins, while the account password, tokens, and <Terminology title="A spare code for when your authenticator is gone" to="/docs/reference/terminology#dashboard-sign-in">recovery codes</Terminology> are stored as hashes and <Terminology title="Sign in with your device, no password or code" to="/docs/reference/terminology#dashboard-sign-in">passkeys</Terminology> as public keys.
- If the key file goes missing, Outpost makes a new key on the next start, turns off the authenticator app, and removes those <Terminology title="A saved token or password the API never hands back" to="/docs/reference/terminology#notifications">secret fields</Terminology> and registry passwords, as described in [Lost Encryption Key](#lost-encryption-key). It is recommended to keep the key with every copy of the database so the authenticator app, the <Terminology title="Where your alerts land, like ntfy, Telegram, or email" to="/docs/reference/terminology#notifications">destinations</Terminology>, and the registry sign-ins keep working after a restore.

## Back Up

1. Stop Outpost so the database files are consistent.

   ```bash
   docker stop outpost
   ```

2. Copy the volume's contents into an archive, using any image that has `tar`.

   ```bash
   docker run --rm \
     --volume outpost-data:/config:ro \
     --volume "$PWD":/backup \
     debian:trixie-slim \
     tar -czf /backup/outpost-data.tgz -C /config .
   ```

3. Start Outpost again.

   ```bash
   docker start outpost
   ```

- With Docker Compose, use `docker compose stop outpost` and `docker compose start outpost`. Compose puts the project name in front of the volume name, such as `outpost_outpost-data`, and `docker volume ls` lists it.
- The archive holds the password hash and the <Terminology title="The file that unlocks your saved secrets" to="/docs/reference/terminology#backup-and-encryption">encryption key</Terminology>, so it is recommended to store it encrypted.

## Restore

:::danger
The second command deletes everything in the current data volume before the backup replaces it.
:::

```bash
docker stop outpost
docker run --rm \
  --volume outpost-data:/config \
  --volume "$PWD":/backup:ro \
  debian:trixie-slim \
  sh -c 'rm -rf /config/* && tar -xzpf /backup/outpost-data.tgz -C /config'
docker start outpost
```

Restored files keep their owner, which needs to match the `PUID` and `PGID` Outpost runs as.

## Lost Password

There's no password reset, because Outpost keeps only a hash of the password.

- A <Terminology title="Sign in with your device, no password or code" to="/docs/reference/terminology#dashboard-sign-in">passkey</Terminology> still signs you in, but changing the password asks for the current one.
- Otherwise, restore a backup from a time you knew the password, or start over as described below.

## Lost Authenticator

- With a <Terminology title="A spare code for when your authenticator is gone" to="/docs/reference/terminology#dashboard-sign-in">recovery code</Terminology>, sign in with it in place of the authenticator code. Then open **Sign-in and security** from the account menu, turn off the authenticator app, and set it up again on your new device.
- With a <Terminology title="Sign in with your device, no password or code" to="/docs/reference/terminology#dashboard-sign-in">passkey</Terminology>, sign in with it and do the same.
- Without either, delete the <Terminology title="The file that unlocks your saved secrets" to="/docs/reference/terminology#backup-and-encryption">encryption key</Terminology> with `docker exec outpost rm /config/keys/installation.key` and run `docker restart outpost`. Outpost then turns off the authenticator app, so you can sign in with the password and set the app up again, but it also removes the <Terminology title="A saved token or password the API never hands back" to="/docs/reference/terminology#notifications">secret fields</Terminology> of notification <Terminology title="Where your alerts land, like ntfy, Telegram, or email" to="/docs/reference/terminology#notifications">destinations</Terminology> and the passwords of private registry sign-ins, as described in [Lost Encryption Key](#lost-encryption-key).

## Lost Encryption Key

If `keys/installation.key` is missing, Outpost makes a new <Terminology title="The file that unlocks your saved secrets" to="/docs/reference/terminology#backup-and-encryption">encryption key</Terminology> and starts. The new key can't open what the old one sealed, so Outpost turns the authenticator app off and deletes its <Terminology title="A spare code for when your authenticator is gone" to="/docs/reference/terminology#dashboard-sign-in">recovery codes</Terminology>, the same as **Turn off** on the **Sign-in and security** page, removes the <Terminology title="A saved token or password the API never hands back" to="/docs/reference/terminology#notifications">secret fields</Terminology> of every notification <Terminology title="Where your alerts land, like ntfy, Telegram, or email" to="/docs/reference/terminology#notifications">destination</Terminology>, and clears the password of every private registry sign-in.

The account, the password, the <Terminology title="Sign in with your device, no password or code" to="/docs/reference/terminology#dashboard-sign-in">passkeys</Terminology>, the sign-ins, the <Terminology title="A key your scripts send to call the API" to="/docs/reference/terminology#api-access">access tokens</Terminology>, the <Terminology title="Where your alerts land, like ntfy, Telegram, or email" to="/docs/reference/terminology#notifications">destinations</Terminology> with their other fields, the registry sign-ins' hosts and usernames, and the history stay. Outpost logs one warning on that start, naming what was removed:

```text
2026-10-24T22:05:00Z WARN state: No encryption key was found at "/config/keys/installation.key", so Outpost made a new one. These saved secrets were locked with the old key and were removed: the authenticator app for <username>, the <name> notification, the <host> registry sign-in. Enter them again in the dashboard.
```

- **Signing in** — Password sign-in asks only for the password until you set the authenticator app up again, and <Terminology title="Sign in with your device, no password or code" to="/docs/reference/terminology#dashboard-sign-in">passkeys</Terminology> keep working.
- **Setting the app up again** — The **Saved secrets were removed** notice at the top of the dashboard links to **Set up the authenticator app**, as described in [Web Dashboard](/docs/features/dashboard/#saved-secrets-notice).
- **Destinations** — A <Terminology title="Where your alerts land, like ntfy, Telegram, or email" to="/docs/reference/terminology#notifications">destination</Terminology> that lost <Terminology title="A saved token or password the API never hands back" to="/docs/reference/terminology#notifications">secret fields</Terminology> is paused until you enter them again with **Edit** on the **Notifications** page, which the notice links to. The others keep working and get the **Saved secrets were removed** alert if they chose it, as described in [Notifications](/docs/features/notifications/#lost-encryption-key).
- **Registry sign-ins** — A private registry sign-in that lost its password keeps its host and username. Checks of private images from that registry fail until you enter the password again with **Edit** under **Private registries** on the **Settings** page, which the notice links to.
- **Nothing to remove** — If no authenticator app was on, no registry sign-in had a password, and no <Terminology title="Where your alerts land, like ntfy, Telegram, or email" to="/docs/reference/terminology#notifications">destination</Terminology> had <Terminology title="A saved token or password the API never hands back" to="/docs/reference/terminology#notifications">secret fields</Terminology>, such as on a fresh install, there's no warning and no notice.

After Outpost makes the new key, the database belongs to that key, so putting the old key file back stops startup, as described in [Encryption Key Doesn't Match](#encryption-key-doesnt-match).

## Encryption Key Doesn't Match

Startup stops with one of these messages, and the server repeats it each time it restarts:

- `The encryption key at "/config/keys/installation.key" doesn't belong to this database. Put back the key file this database was created with, or delete "/config/keys/installation.key" and restart to make a new key, then enter the saved secrets again.` — The key file belongs to another database, such as when the database and the key came from different backups.
- `The encryption key file at "..." is not 32 raw bytes or 64 hexadecimal characters.` — The key file is damaged.

Restore `keys/installation.key` from the same backup as the database. Without it, delete the key file and restart, so Outpost makes a new key as described in [Lost Encryption Key](#lost-encryption-key):

```bash
docker stop outpost
docker run --rm \
  --volume outpost-data:/config \
  debian:trixie-slim \
  rm /config/keys/installation.key
docker start outpost
```

The helper container edits the named volume while Outpost is stopped. For a bind mount, remove the file from the mounted host folder instead.

## Change PUID or PGID With Existing Data

Set the new values, each from `1` through `60000`, and restart the container. Nova recursively changes the complete state directory to the new `PUID:PGID` on every start, including the database and key folders.

## Start Over

Starting over is for when the password is lost and no <Terminology title="Sign in with your device, no password or code" to="/docs/reference/terminology#dashboard-sign-in">passkey</Terminology> or backup can get you back in.

:::danger
Starting over deletes the dashboard account and its browser sessions, every <Terminology title="A key your scripts send to call the API" to="/docs/reference/terminology#api-access">access token</Terminology>, the authenticator app, the <Terminology title="A spare code for when your authenticator is gone" to="/docs/reference/terminology#dashboard-sign-in">recovery codes</Terminology>, the <Terminology title="Sign in with your device, no password or code" to="/docs/reference/terminology#dashboard-sign-in">passkeys</Terminology>, every notification <Terminology title="Where your alerts land, like ntfy, Telegram, or email" to="/docs/reference/terminology#notifications">destination</Terminology>, every private registry sign-in, the **Settings** page's saved values, and the record of images held after a rollback. The history stays.
:::

1. It is recommended to back up the data directory first, as described above.
2. Remove the database and its key, then restart Outpost.

   ```bash
   docker exec outpost sh -c 'rm -rf /config/database /config/keys'
   docker restart outpost
   ```

3. Read the new <Terminology title="One-time code from the log that creates your account" to="/docs/reference/terminology#dashboard-sign-in">setup code</Terminology> with `docker logs outpost` and create the account again, as shown in [Web Dashboard](/docs/features/dashboard/#set-up-your-account).
4. Create new <Terminology title="A key your scripts send to call the API" to="/docs/reference/terminology#api-access">access tokens</Terminology> and update every client that used the old ones.
5. Add the notification <Terminology title="Where your alerts land, like ntfy, Telegram, or email" to="/docs/reference/terminology#notifications">destinations</Terminology> again on the **Notifications** page.
6. Add the private registry sign-ins again and set the **Settings** page back the way you had it.
