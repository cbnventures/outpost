Move from Watchtower to Outpost by translating your settings and labels, and know up front which Watchtower options don't carry over.

## Why Migrate?

1. Gets automatic <Terminology title="restoring the previous container after a failure" to="/docs/reference/terminology#rollback">rollback</Terminology> so an update that breaks a container no longer leaves it down.
2. Keeps anonymous volume data and the new image's defaults through every <Terminology title="swapping a container onto the new image" to="/docs/reference/terminology#recreation">recreation</Terminology>.
3. Runs the updater as a non-root user that only joins the Docker socket's group.
4. Moves to a project that is actively maintained.

## Migration Steps

1. Stop and remove the Watchtower container so the two never update the same container at once.
2. Translate its environment variables into Outpost settings and your container labels with the tables below.
3. If Watchtower pulled private images, add a sign-in for each registry under **Private registries** on Outpost's **Settings** page, as shown in [Private Registries](/docs/getting-started/private-registries/#add-a-sign-in).
4. Turn on **Monitor only** on Outpost's **Settings** page and check the first <Terminology title="per-container results of a cycle" to="/docs/reference/terminology#report">report</Terminology>.
5. If scripts or Prometheus called Watchtower's API, create an <Terminology title="scoped key that scripts use to call the API" to="/docs/reference/terminology#access-token">access token</Terminology> for each one on the dashboard's **Access tokens** page.
6. If Watchtower sent notifications, add a <Terminology title="a place Outpost sends alerts to" to="/docs/reference/terminology#destination">destination</Terminology> for each service on the dashboard's **Notifications** page, and select **Send test**.
7. Turn off **Monitor only** once the results look right.

Container names passed as arguments, such as `watchtower nginx redis`, have no equivalent. It is recommended to use <Terminology title="whether containers are opted out or opted in" to="/docs/reference/terminology#label-mode">opt-in mode</Terminology> with labels instead.

## Labels

| Watchtower                                    | Outpost                               | Notes                                                                                                                                                                  |
|-----------------------------------------------|---------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `com.centurylinklabs.watchtower.enable`       | `io.cbnventures.outpost.enable`       | Outpost accepts only lowercase `true` or `false`.                                                                                                                      |
| `com.centurylinklabs.watchtower.monitor-only` | `io.cbnventures.outpost.monitor-only` | `true` makes the container <Terminology title="report updates without recreating containers" to="/docs/reference/terminology#monitor-only">monitor-only</Terminology>. |
| `com.centurylinklabs.watchtower.depends-on`   | None                                  | Compose `depends_on` is read automatically.                                                                                                                            |
| `com.centurylinklabs.watchtower.scope`        | None                                  |                                                                                                                                                                        |
| `com.centurylinklabs.watchtower.no-pull`      | None                                  |                                                                                                                                                                        |
| `com.centurylinklabs.watchtower.stop-signal`  | None                                  | Docker uses the container's own stop signal.                                                                                                                           |
| `com.centurylinklabs.watchtower.lifecycle.*`  | None                                  | Lifecycle hooks are not supported.                                                                                                                                     |

Outpost ignores Watchtower labels entirely. You can keep them while you migrate, but they have no effect.

## API and Metrics

- **Port** — The API listens on port `3000` rather than Watchtower's `8080`, so update port mappings, scripts, and scrape targets.
- **Tokens** — Watchtower's one shared token becomes an <Terminology title="scoped key that scripts use to call the API" to="/docs/reference/terminology#access-token">access token</Terminology> for each client, with only the <Terminology title="what an access token is allowed to do" to="/docs/reference/terminology#scope">scopes</Terminology> it needs. Clients still send it as `Authorization: Bearer`, so only the token's value changes.
- **Update** — Watchtower's `/v1/update` becomes `POST /v1/update`, which returns `202` or `409` instead of waiting for the run to finish. A `GET`, which is what plain `curl` sends, gets `404` with the code `not_found`.
- **Single images** — `POST /v1/update` ignores query parameters, so Watchtower's `?image=` has no equivalent there. To check one container, send its ID to `POST /api/v1/checks`, as shown in [HTTP API and Metrics](/docs/features/http-api-and-metrics/#start-a-check).
- **Status** — `GET /v1/status` is new and returns the latest <Terminology title="per-container results of a cycle" to="/docs/reference/terminology#report">report</Terminology> as JSON.
- **Metrics** — `/metrics` uses `outpost_*` names, so dashboards and alerts built on `watchtower_*` metrics need updating. See [HTTP API and Metrics](/docs/features/http-api-and-metrics/#metrics) for the list.

## Behavior Differences

- **Rollback** — A new container that stops or turns unhealthy is replaced by the previous one.
- **Self-updates** — Like Watchtower, Outpost updates its own container by default, but last in each check and through a helper container that puts the old one back if the new one fails. To keep it on its current image, label it `io.cbnventures.outpost.enable=false`, and in opt-in mode, label it `io.cbnventures.outpost.enable=true` to let it update itself.
- **Cleanup default** — Old images are removed after an update unless you turn off **Clean up old images** in **Settings**.
- **Shared network namespaces** — Containers with `network_mode: container:...` or `service:...` are skipped and need updating by hand.
- **Registry logins** — Outpost doesn't read Docker's `config.json` or run credential helpers such as `credsStore`. Add each login on the **Settings** page instead; see [Private Registries](/docs/getting-started/private-registries/#add-a-sign-in).
